# 知识考察

## 以下代码有什么问题

```c
int main() {
    char a;
    char *str = &a;
    strcpy(str, "hello");
    printf(str);
    return 0;
}
```

### 问题分析

| 问题 | 说明 |
|------|------|
| **缓冲区溢出** | `a` 只有1字节,但 `strcpy` 写入6字节(含`\0`) |
| **栈溢出** | 越界写入破坏栈上其他数据 |
| **printf格式漏洞** | `printf(str)` 若str含`%`会被解析为格式符 |

### 正确写法

```c
int main() {
    char str[16];           // 分配足够缓冲区
    strncpy(str, "hello", sizeof(str) - 1);
    str[sizeof(str) - 1] = '\0';
    printf("%s\n", str);    // 指定格式符
    return 0;
}
```

## 32位机器的指针是多少位

**32位机器的指针是32位(4字节)**。

指针大小由**地址总线宽度**决定：

| 架构 | 指针大小 | 地址空间 |
|------|----------|----------|
| 16位(8086) | 2字节 | 64KB |
| 32位(x86) | 4字节 | 4GB |
| 64位(x86_64) | 8字节 | 16EB(理论) |

> **注意**:某些64位系统使用LLP64模型(如Windows),`long`仍为4字节,但指针是8字节。

## 隐式类型转换规则

如下代码的输出结果是?为什么?

```c
#include <stdio.h>

int main(void) {
    unsigned int a = 6;
    int b = -20;
    if (a + b > 6) printf("a+b > 6\n"); else printf("a+b < 6\n");
    return 0;
}
```

程序输出：

```
a+b > 6
```

### 原因分析

当 `unsigned int` 和 `int` 混合运算时,编译器将 `int` 隐式转换为 `unsigned int`:

```c
// b = -20 的补码表示(32位)
// 原码: 0x80000014
// 反码: 0xFFFFFFEB
// 补码: 0xFFFFFFEC = 4294967276 (作为无符号数)

a + b = 6 + 4294967276 = 4294967282 > 6
```

### C语言隐式转换规则(Usual Arithmetic Conversions)

```
long double > double > float > unsigned long long > long long >
unsigned long > long > unsigned int > int
```

> **规则**:运算前,较小类型总是向较大类型转换;有符号与无符号混合时,有符号转无符号。

## 写一个MAX宏

### 基础版本

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
```

### 问题与改进

| 问题 | 示例 | 解决方案 |
|------|------|----------|
| **副作用** | `MAX(x++, y++)` 多次自增 | 使用局部变量保存 |
| **类型安全** | 不同类型比较可能警告 | GCC扩展 `typeof` |
| **不支持语句** | 不能作为单条语句使用 | `do{}while(0)` 包裹 |

### Linux内核版本(推荐)

```c
#define max(x, y) ({                \
    typeof(x) _max1 = (x);          \
    typeof(y) _max2 = (y);          \
    (void) (&_max1 == &_max2);      \
    _max1 > _max2 ? _max1 : _max2; })

// (void) (&_max1 == &_max2) 用于编译期类型检查
```

## 复杂变量定义解析

```c
int a;              // a) 整型数
int *a;             // b) 指向整型的指针
int **a;            // c) 指向指针的指针(二级指针)
int a[10];          // d) 10个整型的数组
int *a[10];         // e) 10个指向整型的指针数组([]优先级高)
int (*a)[10];       // f) 指向10个整型数组的指针
int (*a)(int);      // g) 指向函数的指针(参数int,返回int)
int (*a[10])(int);  // h) 10个函数指针的数组
```

### 记忆技巧:右左法则

```
int (*a[10])(int);
     ^a
      ^[10]      → a是包含10个元素的数组
     ^(*)         → 数组元素是指针
            ^(int) → 指向参数为int的函数
     ^int          → 函数返回int

结论:a是包含10个指针的数组,每个指针指向参数为int、返回int的函数
```

## 中断服务程序(ISR)的规范

### 错误示例分析

```c
__interrupt double compute_area(double radius) {  // 错误1:ISR不能有参数
    double area = PI * radius * radius;            // 错误2:浮点运算不可重入
    printf("Area = %f", area);                      // 错误3:printf非可重入,且耗时
    return area;                                    // 错误4:ISR不能有返回值
}
```

### ISR编写规范

| 规范 | 说明 |
|------|------|
| **无参数无返回值** | `void ISR_NAME(void)` |
| **不可重入函数** | 避免 `printf`、`malloc`、浮点运算 |
| **快速执行** | 只做必要操作,复杂处理放下半部 |
| **保存上下文** | 编译器自动处理,但避免内联汇编干扰 |
| **清中断标志** | 退出前清除中断源,防止重复进入 |

### 正确示例

```c
volatile uint32_t g_irq_count = 0;

void TIM2_IRQHandler(void) {
    if (TIM2->SR & TIM_SR_UIF) {
        TIM2->SR &= ~TIM_SR_UIF;  // 清中断标志
        g_irq_count++;             // 简单计数
        // 复杂处理交给tasklet/workqueue
    }
}
```

## 宏函数与内联函数的区别

| 特性 | 宏函数 (`#define`) | 内联函数 (`inline`) |
|------|-------------------|---------------------|
| **处理阶段** | 预处理器(文本替换) | 编译器(语义分析) |
| **类型检查** | 无 | 有 |
| **调试** | 困难(无符号信息) | 可调试 |
| **作用域** | 从定义处到文件末尾 | 遵循函数作用域规则 |
| **代码膨胀** | 可能严重 | 编译器控制 |
| **副作用** | 参数可能多次求值 | 正常函数语义 |
| **适用场景** | 条件编译、简单表达式 | 频繁调用的小函数 |

### 示例对比

```c
// 宏:无类型检查,有副作用风险
#define SQUARE(x) ((x) * (x))
int a = 5;
int b = SQUARE(a++);  // 展开为 ((a++) * (a++)),未定义行为!

// 内联:类型安全,无副作用
inline int square(int x) {
    return x * x;
}
int c = square(a++);  // 正确:先求值,再传入
```

## 内联函数可以递归吗

**不可以真正内联**。

递归内联会导致无限展开,编译器会拒绝：

```c
inline int factorial(int n) {
    return (n <= 1) ? 1 : n * factorial(n - 1);  // 编译器不会内联
}
```

>   内联函数通常是不可以递归的。这是因为内联函数的目的在于消除函数调用开销，而递归调用会导致多个函数调用，这与内联的初衷相悖。
>
>   递归内联函数的问题：
>
>   1.  **无法真正实现**：如果一个内联函数自身递归，那么编译器在处理时将会出现无限的展开，导致编译错误或超出编译器处理能力。
>   2.  **开销问题**：即使编译器能够处理，递归情况下仍然会有多次的栈帧创建和管理，最终可能不会带来预期的性能提升。

编译器行为：

| 情况 | 结果 |
|------|------|
| 简单递归 | 编译器忽略 `inline`,作为普通函数处理 |
| 强制内联 (`__attribute__((always_inline))`) | 编译错误或栈溢出 |
| 尾递归优化 | 某些编译器可优化为循环,但非内联 |

【示例】以下展示了一个试图使用内联函数进行递归的代码：

```c
//example.c

#include <stdio.h>

inline int factorial(int n) {
    return (n <= 1) ? 1 : n * factorial(n - 1);
}

int main() {
    int result = factorial(5); // 理论上这里是可以通过，但实际效果未必如愿
    printf("result = %d\n", result);
    return 0;
}

```

编译报错：

```c
$ gcc example.c
/usr/bin/ld: /tmp/cc7c4xto.o: in function `main':
example.c:(.text+0xe): undefined reference to `factorial'
collect2: error: ld returned 1 exit status
```

但加上factorial函数的声明后就可以正常编译执行了：

```c
int factorial(int n);
```

## gets()函数的问题

```c
#include <stdio.h>

int main(void) {
    char buff[10];
    gets(buff);  // 危险!不检查缓冲区大小
    printf("[%s]\n", buff);
    return 0;
}
```

### 问题分析

| 问题 | 说明 |
|------|------|
| **缓冲区溢出** | `gets` 不限制输入长度,可任意覆盖栈 |
| **已废弃** | C11标准已移除 `gets`,GCC编译报错 |
| **安全替代** | 使用 `fgets(buff, sizeof(buff), stdin)` |

### 正确写法

```c
char buff[10];
if (fgets(buff, sizeof(buff), stdin) != NULL) {
    // 移除末尾换行符
    buff[strcspn(buff, "\n")] = '\0';
    printf("[%s]\n", buff);
}
```

## strcpy()的安全问题

### 漏洞示例:栈溢出绕过密码验证

```c
#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[]) {
    int flag = 0;
    char passwd[10];

    strcpy(passwd, argv[1]);  // 危险:不检查长度

    if (strcmp("LinuxGeek", passwd) == 0) {
        flag = 1;
    }

    if (flag) {
        printf("Password cracked\n");
    }
    return 0;
}
```

### 攻击原理

```
栈布局：
高地址 |  flag (4字节)  |  ← 被长密码覆盖为1
       |  passwd[10]    |  ← 输入超长密码溢出
低地址
```

```bash
$ ./psswd aaaaaaaaaaaaa
Password cracked   # flag被覆盖为非零
```

### 安全替代方案

```c
// 方案1:strncpy(注意不保证\0结尾)
strncpy(passwd, argv[1], sizeof(passwd) - 1);
passwd[sizeof(passwd) - 1] = '\0';

// 方案2:strlcpy(BSD,更安全)
strlcpy(passwd, argv[1], sizeof(passwd));

// 方案3:编译器保护(现代GCC默认启用)
// -fstack-protector 检测栈溢出并终止程序
```

## 内存泄漏检测

### 问题代码

```c
void main(void) {
    char *ptr = malloc(10);
    if (NULL == ptr) {
        return;           // 路径1:无泄漏(ptr为NULL)
    }
    // Do some processing
    return;               // 路径2:泄漏!未free(ptr)
}
```

### 修复方案

```c
int main(void) {
    char *ptr = malloc(10);
    if (ptr == NULL) {
        return EXIT_FAILURE;
    }

    // Do some processing

    free(ptr);            // 确保释放
    ptr = NULL;           // 防止悬空指针
    return EXIT_SUCCESS;
}
```

## free()的悬空指针问题

### 问题代码

```c
char *ptr = malloc(10);
strcpy(ptr, "freeze");

while (*ptr != 'z') {
    ptr++;  // 指针偏移！
}

free(ptr);  // 错误：ptr已不是malloc返回的地址
```

### 问题分析

| 输入 | 行为 | 结果 |
|------|------|------|
| `"zebra"` | `ptr[0]=='z'`，循环不执行 | `free`正确 |
| `"freeze"` | 循环执行，`ptr`偏移到`'z'`位置 | `free`传入中间地址，崩溃 |

### 正确写法

```c
char *ptr = malloc(10);
char *original = ptr;  // 保存原始指针

strcpy(ptr, argv[1]);

while (*ptr != 'z' && *ptr != '\0') {
    ptr++;
}

free(original);  // 释放原始地址
```

## _exit与exit的区别

### 问题代码

```c
#include <stdlib.h>

void cleanup(void) {
    printf("Cleanup\n");
}

int main(void) {
    atexit(cleanup);  // 注册退出处理函数
    _exit(0);         // 不调用cleanup！
}
```

### 对比

| 特性 | `exit()` | `_exit()`/_Exit() |
|------|----------|-------------------|
| **atexit处理** | 调用注册的函数 | **不调用** |
| **stdio刷新** | 刷新所有缓冲区 | **不刷新** |
| **临时文件** | 删除 | **不删除** |
| **使用场景** | 正常退出 | 子进程退出、`fork()`后 |

### 典型场景

```c
// fork后子进程应使用_exit，避免重复刷新父进程的缓冲区
pid_t pid = fork();
if (pid == 0) {
    // 子进程
    execvp(cmd, args);
    _exit(127);  // exec失败，直接退出
}
```

这是因为_exit()函数的使用,该函数并没有调用atexit()等函数清理。如果使用atexit()就应当使用exit()或者"return"与之相配合。

## 返回本地变量的地址

问:下面代码有问题吗?如果有,该怎么修改?

```c
#include <stdio.h>

int *inc(int val) {
    int a = val;
    a++;
    return &a;
}

int main(void) {
    int a = 10;
    int *val = inc(a);
    printf("\n Incremented value is equal to [%d] \n", *val);

    return 0;
}
```

答:尽管上面的程序有时候能够正常运行,但是在"inc()"中存在严重的漏洞。这个函数返回本地变量的地址。

因为本地变量的生命周期就是"inc()"的生命周期,所以在inc结束后,使用本地变量会发生不好的结果。这可以通过将main()中变量"a"的地址来避免,这样以后还可以修改这个地址存储的值。

## 详细解释栈帧?

栈帧是调用栈上的一个逻辑单元,它为每个正在执行的函数调用(或过程调用)提供独立的存储空间。每当一个函数被调用时,一个新的栈帧就会被压入调用栈;当函数执行完毕返回时,对应的栈帧就会被弹出。

### 栈帧的组成部分

一个典型的栈帧通常包含以下几个主要部分(具体组成和顺序可能因编译器、操作系统和CPU架构而异,但核心思想是相同的):

1.  函数参数:被调用函数接收的参数。这些参数通常在函数调用前被压入栈中,或者通过寄存器传递。
2.  返回地址:调用函数执行完毕后,程序应该返回到调用函数中的哪条指令继续执行。这个地址在函数调用时被压入栈中。
3.  旧的栈基址/帧指针:在进入新函数时,当前函数的栈帧会保存调用者的栈基址。这个指针用于在函数返回时恢复调用者的栈帧,并提供一个固定的参考点来访问栈帧中的数据。
4.  局部变量:被调用函数内部定义的非静态局部变量。这些变量在函数执行期间分配在栈帧中,函数返回时自动销毁。
5.  临时变量:编译器为了表达式计算或优化而生成的临时变量。
6.  寄存器保存区:为了避免被调用函数修改调用者使用的寄存器,被调用函数会将一些重要的寄存器(如通用寄存器、浮点寄存器等)的值保存到栈帧中,并在返回前恢复它们。

### 栈指针和帧指针

-   栈指针:指向当前栈的顶部(栈顶地址)。栈是向下增长的(从高地址向低地址增长),所以栈指针总是指向栈中最后一个被压入的元素的地址。当数据被压入栈时,栈指针减小;当数据从栈中弹出时,栈指针增大。
-   帧指针:指向当前栈帧的底部(或某个固定位置,如旧的栈基址)。帧指针在函数执行期间保持不变,它提供了一个稳定的基准,使得函数可以通过相对于帧指针的偏移量来访问其参数和局部变量,而无需关心栈指针的动态变化。

### 函数调用过程中栈帧的变化(以x86/x64为例)

一个简单的函数调用,说明栈帧的创建和销毁过程：

```
void func_b(int y) {
    int z = y + 1;
    // ...
}

void func_a(int x) {
    int a = x * 2;
    func_b(a);
    // ...
}

int main() {
    func_a(10);
    return 0;
}
```

1、`main` 函数的栈帧：

-   `main` 函数开始执行,其栈帧被创建。
-   `main` 函数调用 `func_a(10)`。

2、调用 `func_a` :

-   参数 `10` 被压入栈中(或通过寄存器传递)。
-   `main` 函数的返回地址(即 `func_a` 调用后的下一条指令地址)被压入栈中。
-   控制权转移到 `func_a` 的入口点。

3、`func_a` 函数的序言：

-   `func_a` 将 `main` 函数的旧帧指针(`EBP_main`)压入栈中。
-   `EBP` 寄存器更新为当前的 `ESP` 值,作为 `func_a` 的新帧指针(`EBP_func_a`)。
-   `ESP` 寄存器减小,为 `func_a` 的局部变量(如 `a`)分配空间。
-   此时,`func_a` 的栈帧已经建立。

4、`func_a` 调用 `func_b`:

-   参数 `a` 的值被压入栈中(或通过寄存器传递)。
-   `func_a` 的返回地址(即 `func_b` 调用后的下一条指令地址)被压入栈中。
-   控制权转移到 `func_b` 的入口点。

5、`func_b` 函数的序言：

-   `func_b` 将 `func_a` 函数的旧帧指针(`EBP_func_a`)压入栈中。
-   `EBP` 寄存器更新为当前的 `ESP` 值,作为 `func_b` 的新帧指针(`EBP_func_b`)。
-   `ESP` 寄存器减小,为 `func_b` 的局部变量(如 `z`)分配空间。
-   此时,`func_b` 的栈帧已经建立。

6、`func_b` 函数的执行和返回：

-   `func_b` 执行完毕。
-   `ESP` 寄存器恢复到 `EBP_func_b` 的值,释放局部变量空间。
-   从栈中弹出 `EBP_func_a`,恢复 `EBP` 寄存器。
-   从栈中弹出 `func_a` 的返回地址,并跳转到该地址,控制权返回给 `func_a`。
-   `func_b` 的栈帧被销毁。

7、`func_a` 函数的执行和返回：

-   `func_a` 执行完毕。
-   `ESP` 寄存器恢复到 `EBP_func_a` 的值,释放局部变量空间。
-   从栈中弹出 `EBP_main`,恢复 `EBP` 寄存器。
-   从栈中弹出 `main` 的返回地址,并跳转到该地址,控制权返回给 `main`。
-   `func_a` 的栈帧被销毁。

## C语言怎么检查死锁的存在?

在C语言中检查死锁的存在,可以通过**静态代码分析、动态调试工具、死锁检测算法**以及**日志追踪**等方法实现。以下是具体方法和工具,结合搜索结果中的关键信息进行说明：

### 使用调试工具定位死锁

>   GDB(GNU Debugger)

步骤：

1.  编译时添加调试信息:`gcc -g -pthread your_program.c -o your_program`。
2.  启动GDB并运行程序:`gdb ./your_program`,输入`run`执行。
3.  当程序卡死时,使用info threads查看所有线程状态,thread n切换线程,backtrace查看调用栈,定位阻塞在锁的位置。
4.  检查锁的状态:通过p mutex_var打印互斥锁变量,分析持有者(如__owner字段)。

**适用场景**:适用于运行时死锁的即时分析,需复现问题。

>   Valgrind Helgrind

步骤：

1.  编译时禁用优化:`gcc -O0 -g -pthread your_program.c -o your_program`。
2.  使用Helgrind运行:`valgrind --tool=helgrind ./your_program`。
3.  分析输出报告,Helgrind会直接指出锁的顺序问题或死锁位置。

优势:自动检测潜在的死锁和竞争条件,无需手动复现。

### 代码审查与静态分析

1.  **手动检查锁的顺序**
    -   确保所有线程按固定顺序获取锁(如先锁A再锁B),避免循环等待。
    -   示例:若线程1先锁A后锁B,线程2也必须按相同顺序。
2.  **静态分析工具**
    -   Clang ThreadSanitizer(TSan):编译时添加-fsanitize=thread选项,运行时检测数据竞争和死锁。
    -   Coverity、PVS-Studio:商业工具可扫描代码中的潜在死锁模式。

### 动态检测算法(资源分配图)

**银行家算法扩展**

-   原理:通过维护资源分配矩阵(Allocation)、请求矩阵(Request)和可用资源向量(Available),检测系统是否处于安全状态。
-   实现步骤：
    1.  初始化数据结构(如矩阵和向量)。
    2.  遍历进程,检查是否存在可满足的请求(`Request[i] ≤ Work`)。
    3.  若所有进程可完成,则无死锁;否则存在死锁。

**超时机制**

-   使用pthread_mutex_trylock或带超时的锁(如pthread_mutex_timedlock),若超时未获取锁则释放已持有资源,避免无限等待。

### 日志与运行时监控

**添加日志记录**

-   在锁操作前后打印日志,记录线程ID、锁变量和操作类型(加锁/解锁)。

-   示例：

    ```
    printf("Thread %ld: Locking mutex %p\n", pthread_self(), &mutex);
    pthread_mutex_lock(&mutex);
    printf("Thread %ld: Locked mutex %p\n", pthread_self(), &mutex);
    ```

**死锁检测库**

-   Boost.Thread:提供锁顺序检查工具。
-   libdlock:专用于死锁检测的开源库,可集成到项目中。

### 总结与工具选择建议

| **方法**       | **适用阶段**  | **优点**               | **缺点**       |
| -------------- | ------------- | ---------------------- | -------------- |
| **GDB调试**    | 运行时        | 直接定位阻塞点         | 需复现问题     |
| **Helgrind**   | 运行时        | 自动检测潜在死锁       | 性能开销大     |
| **静态分析**   | 编码后/编译前 | 提前发现代码问题       | 可能误报       |
| **银行家算法** | 系统设计      | 理论完备,适合资源管理 | 实现复杂       |
| **日志追踪**   | 测试/生产环境 | 无侵入,适合长期监控   | 需人工分析日志 |

**推荐流程**:开发阶段用静态分析工具(如TSan)预防;测试阶段结合GDB和Helgrind动态检测;生产环境添加日志监控。

## 解释堆溢出(Heap Overflow)和栈溢出(Stack Overflow)的概念。

堆溢出(Heap Overflow)和栈溢出(Stack Overflow)是常见的编程错误,指的是在程序执行时写入超过所分配内存空间大小的数据。

-   堆溢出(Heap Overflow):当程序向动态分配的堆内存中写入超过预分配大小的数据时发生。通常情况下,程序使用诸如malloc()、new等函数从堆中分配内存。如果程序没有正确管理分配的内存,并且向已分配的堆块写入超过其边界范围之外的数据,就会导致堆溢出。这可能导致覆盖相邻内存区域或破坏重要数据结构,进而引发崩溃或安全漏洞。
-   栈溢出(Stack Overflow):当函数调用层级过多或递归无限循环时,函数调用栈可能会耗尽可用空间并超出其容量限制,导致栈溢出。每次函数调用时,一部分内存被用于保存函数参数、局部变量和返回地址等信息。如果栈空间被大量函数调用占满,并且新的函数调用无法再压入栈中,就会发生栈溢出。这通常会导致程序异常终止或崩溃。

堆溢出和栈溢出都是常见的安全漏洞,攻击者可以利用这些漏洞来执行恶意代码或破坏程序的正常行为。因此,在编写程序时要避免这些错误,并进行适当的边界检查和内存管理。

## 栈溢出(stack overflow)是什么?为什么会发生这种情况?如何避免它?

栈溢出(stack overflow)是指当程序在执行过程中,向栈中压入的数据超过了栈的最大容量,导致栈空间被耗尽而无法继续正常运行。

栈溢出通常发生在以下情况下：

-   递归调用:如果递归调用没有正确结束条件或者递归深度过大,每次函数调用都会占用一部分栈空间,当栈空间被耗尽时就会发生栈溢出。
-   局部变量占用过多空间:如果一个函数内声明的局部变量或数组较大,或者有多个嵌套的函数调用时,会占用较多的栈空间,超过了可分配给栈的限制。
-   递归数据结构:某些数据结构(如链表、二叉树等)在进行遍历或操作时使用递归算法,并且数据规模太大,也可能导致栈溢出。

为了避免栈溢出问题,可以采取以下措施：

-   优化算法和代码:确保递归算法有正确的结束条件,并尽量减少递归深度。对于复杂的逻辑处理,考虑使用迭代代替递归。
-   减小局部变量和数组的空间占用:合理设计数据结构,减小栈帧中局部变量和数组的大小。
-   使用堆内存:对于较大的数据结构或需要动态分配的内存,可以使用堆内存(通过malloc()、new等函数)来避免栈溢出。
-   增加栈空间限制:某些编程语言或编译器提供了设置栈空间大小的选项,可以适当增加栈的容量。

## c的函数的入参是存放在哪里?所有入参都是栈吗?

在C语言中,函数的入参(实际参数)存储位置和传递方式取决于调用约定和参数类型。以下是详细分析：

### 入参存储位置

>   栈内存(Stack)

-   大多数情况下:函数的入参通过栈传递,尤其是x86架构的C程序。调用函数时,实参按从右向左的顺序压入栈中,随后压入返回地址和调用者的栈帧信息。
    -   **示例**:`func(a, b)`的调用中,`b`先压栈,`a`后压栈,最后压入返回地址。
    -   **寻址方式**:被调用函数通过栈基址寄存器(如`ebp`)的偏移量访问参数。例如,第一个参数位于`8(%ebp)`(32位系统)。
-   特点：
    -   参数在栈中是临时存储的,函数返回后自动释放。
    -   值传递时,形参是实参的副本,修改形参不影响实参。

>   寄存器(Register)

-   优化场景:现代编译器(如GCC)可能使用寄存器传递参数(如x86-64的rdi、rsi等),以减少栈操作开销。
-   **规则**:参数较少且满足寄存器调用约定(如System V ABI)时优先使用寄存器。
-   **混合传递**:当寄存器不足时,剩余参数仍通过栈传递。

>   静态/全局区

-   **特殊情况**:若实参是全局变量或静态变量,其存储位置在全局数据区(静态区),而非栈中。但传递时仍会复制其值或地址到栈/寄存器。

### 是否所有入参都在栈中?

**否**,入参的存储位置取决于以下因素：

1.  调用约定：
    -   `cdecl`(C默认):参数从右向左压栈,调用者清理栈。
    -   `fastcall`:部分参数通过寄存器传递。
2.  参数类型和数量：
    -   基本类型(如`int`)可能通过寄存器或栈传递。
    -   结构体或大对象通常通过栈传递(或隐式传递指针)。
3.  编译器优化：
    -   编译器可能内联函数或优化传递方式,跳过栈操作。

### 总结

| 场景                   | 存储位置         | 特点                              |
| ---------------------- | ---------------- | --------------------------------- |
| **普通参数(x86)**    | 栈内存           | 从右向左压栈,通过`ebp`偏移寻址。 |
| **少量参数(x86-64)** | 寄存器           | 减少栈操作,提升性能。            |
| **全局变量作为实参**   | 全局数据区       | 传递时复制值或地址到栈/寄存器。   |
| **大对象(如结构体)** | 栈(或隐式指针) | 可能压栈或传递指针。              |

## 补充:常见C语言陷阱与最佳实践

### 数组与指针的区别

```c
// 数组和指针不同
char arr[10];
char *ptr = arr;

// arr是数组类型,ptr是指针类型
printf("%zu\n", sizeof(arr));  // 输出10
printf("%zu\n", sizeof(ptr));  // 输出指针大小(4或8)
```

### 结构体内存对齐

```c
struct Bad {
    char c;    // 1字节
    int i;     // 4字节,会有3字节填充
};

struct Good {
    int i;     // 4字节
    char c;    // 1字节,后面会有3字节填充,但总大小更小
};

printf("%zu\n", sizeof(struct Bad));  // 输出8(不是5)
printf("%zu\n", sizeof(struct Good)); // 输出8
```

### 避免空指针解引用

```c
void process(int *p) {
    if (p == NULL) return;  // 先检查
    *p = 10;  // 安全访问
}
```

### 字符串操作安全

```c
// 危险:可能导致缓冲区溢出
char buf[10];
strcpy(buf, "Hello, World!");  // 错误!

// 安全:使用strncpy或snprintf
strncpy(buf, "Hello", sizeof(buf)-1);
buf[sizeof(buf)-1] = '\0';
```

### 使用const保护数据

```c
// 函数不修改传入的数组
void print_array(const int *arr, size_t n) {
    for (size_t i = 0; i < n; i++) {
        printf("%d ", arr[i]);  // 可以读取
        // arr[i] = 0;  // 错误:不能修改
    }
}
```
