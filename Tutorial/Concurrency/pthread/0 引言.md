# 引言

## 进程与线程的关系

进程是操作系统资源分配的基本单位，线程是CPU调度和执行的基本单位。一个进程可以包含多个线程，这些线程共享进程的资源（如内存空间、文件描述符等），但拥有独立的执行流。

```
进程（资源容器）
├── 线程1（执行单元）
├── 线程2（执行单元）
└── 线程3（执行单元）
```

> **核心区别**：进程拥有独立的地址空间，线程共享同一进程的地址空间。

## 为什么使用线程

| 对比项 | 进程 (fork) | 线程 |
|--------|------------|------|
| 创建开销 | 高（需复制地址空间） | 低（共享地址空间） |
| 内存共享 | 不共享（需IPC） | 直接共享 |
| 切换开销 | 高（需切换页表） | 低（只需切换寄存器） |
| 通信方式 | IPC（管道、消息队列等） | 直接读写共享内存 |

## 线程的本质

线程是进程内部的一个**独立控制流/执行序列**。即使不显式使用线程，进程内部也至少存在一个执行线程（主线程）。

> **注意**：单核处理器上，同一时刻只能运行一个线程。多线程的"同时执行"感是通过CPU时间片轮转实现的快速切换。

## 线程的优缺点

### 优点
- **创建开销小**：比创建进程快得多
- **通信简单**：共享内存，无需复杂IPC
- **响应性好**：一个线程阻塞不影响其他线程

### 缺点
- **编程复杂**：需处理竞态条件、死锁等同步问题
- **调试困难**：执行顺序不确定，bug难以复现
- **性能陷阱**：单处理器上，盲目拆分任务不一定更快

## 线程的应用场合

1. **保持界面响应**：GUI程序中，主线程处理界面，工作线程执行耗时操作
2. **并行处理**：同时处理输入、计算、输出（如视频编解码）
3. **高并发服务**：Web服务器同时处理多个客户端连接
4. **多核利用**：计算密集型任务分配到多个CPU核心

## 为什么使用多线程

1. **避免阻塞**：单线程阻塞会导致整个进程挂起
2. **避免CPU空转**：I/O等待期间（网络、磁盘），CPU可处理其他任务
3. **提升效率**：线程切换比进程切换快得多，共享内存减少数据拷贝
