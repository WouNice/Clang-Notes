# 底层解析

## pthread_create 的实现流程

### 初始化和准备工作

- 检查 `__libc_single_threaded` 标志，判断是否为多线程模式
- 执行延迟初始化（首次创建线程时）
- 获取线程属性 `pthread_attr`，解析栈大小、保护区大小、调度参数等

### 分配线程控制块（TCB）

```c
// 分配 pthread 结构体
struct pthread *pd = allocate_stack(mem, attr, &stackaddr, &stacksize);

// 设置线程函数和参数
pd->start_routine = start_routine;
pd->arg = arg;

// 设置栈信息
pd->stackblock = stackaddr;
pd->stackblock_size = stacksize;
pd->guardsize = guardsize;
```

### 设置线程状态与标志

- 初始化 `cancelhandling`、`flags`、`exiting` 等状态标志
- 如果线程属性指定为 C11 线程，设置 `c11` 标志

### 配置调度信息

- 复制父线程的调度策略 `schedpolicy` 和参数 `schedparam`
- 如果属性指定了显式调度参数，则覆盖默认值

### 信号屏蔽设置

- 复制父线程的信号掩码到 `sigmask`
- 临时屏蔽所有信号，防止新线程在启动时受到干扰

### 线程同步与锁的设置

- 初始化 `lock` 和 `setxid_futex`
- 如果启用调试模式，设置 `stopped_start` 标志并加锁

### 创建内核线程

调用 `create_thread` → `clone3` 系统调用：

```c
struct kernel_clone_args args = {
    .flags      = CLONE_VM | CLONE_FS | CLONE_FILES |
                  CLONE_SIGHAND | CLONE_THREAD | CLONE_SYSVSEM |
                  CLONE_SETTLS | CLONE_PARENT_SETTID |
                  CLONE_CHILD_CLEARTID,
    .pidfd      = parent_tidptr,
    .child_tid  = child_tidptr,
    .parent_tid = parent_tidptr,
    .exit_signal    = 0,  // 线程退出不发信号给父进程
    .stack      = newsp,  // 用户态栈顶
    .tls        = tls,    // TLS 地址
};

return kernel_clone(&args);
```

### clone 标志位含义

| 标志 | 作用 |
|------|------|
| `CLONE_VM` | 共享内存空间（mm_struct） |
| `CLONE_FS` | 共享文件系统信息（fs_struct） |
| `CLONE_FILES` | 共享文件描述符表（files_struct） |
| `CLONE_SIGHAND` | 共享信号处理函数（sighand_struct） |
| `CLONE_THREAD` | 加入同一线程组（共享信号结构） |
| `CLONE_SYSVSEM` | 共享 System V 信号量 |
| `CLONE_SETTLS` | 设置线程局部存储 |
| `CLONE_PARENT_SETTID` | 父线程写入子线程 TID |
| `CLONE_CHILD_CLEARTID` | 子线程退出时清零 TID 并唤醒 futex |

### 父子线程分道扬镳

```
父线程路径：
  kernel_clone 返回子线程 TID → 恢复父线程信号掩码 → 返回 pthread_create

子线程路径：
  kernel_clone 返回 0 → 进入 start_thread → 执行用户函数
```

## start_thread：子线程的启动

```c
static int start_thread(void *arg)
{
    struct pthread *pd = arg;

    // 1. 如果设置了 stopped_start，等待父线程解锁
    if (__glibc_unlikely(pd->stopped_start))
        lll_lock(pd->lock, LLL_PRIVATE);

    // 2. 初始化线程环境
    __ctype_init();

    // 3. 注册 TLS（如果启用 rseq）
    if (pd->rseq_area != NULL)
        (void) rseq_register_current_thread();

    // 4. 设置取消点
    pthread_setcanceltype(PTHREAD_CANCEL_ASYNCHRONOUS, NULL);
    pthread_setcancelstate(PTHREAD_CANCEL_ENABLE, NULL);

    // 5. 执行用户线程函数
    void *ret = pd->start_routine(pd->arg);

    // 6. 保存返回值
    pd->result = ret;

    // 7. 执行清理函数（pthread_cleanup_push 注册的）
    __pthread_cleanup_pop(1);

    // 8. 调用 TLS 析构函数
    __call_tls_dtors();

    // 9. 线程退出
    __nptl_thread_exit();
}
```

## pthread_join 的实现

```c
int __pthread_join(pthread_t threadid, void **thread_return)
{
    struct pthread *pd = (struct pthread *) threadid;

    // 检查线程描述符是否有效
    if (INVALID_NOT_TERMINATED_TD_P(pd))
        return ESRCH;

    // 尝试设置 joinid（CAS操作，防止多个线程同时join）
    if (atomic_compare_and_exchange_bool_acq(&pd->joinid,
                                              THREAD_SELF, NULL))
        return EINVAL;  // 已被其他线程join或已是detached

    // 等待线程结束（通过 futex 等待 TID 变为0）
    pid_t tid;
    while ((tid = atomic_load_acquire(&pd->tid)) != 0) {
        int ret = __futex_abstimed_wait_cancelable64(
            (unsigned int *)&pd->tid, tid,
            clockid, abstime, LLL_SHARED);
        if (ret == ETIMEDOUT || ret == EOVERFLOW) {
            // 超时处理
            pd->joinid = NULL;
            return ret;
        }
    }

    // 获取返回值
    if (thread_return != NULL)
        *thread_return = pd->result;

    // 释放线程控制块资源
    __nptl_free_tcb(pd);

    return 0;
}
```

### CLONE_CHILD_CLEARTID 机制

这是线程同步的关键：

1. 子线程退出时，内核自动将其 `tid` 字段清零
2. 同时触发 futex 唤醒操作
3. 正在 `pthread_join` 中等待的父线程被唤醒

```
子线程退出流程：
  用户函数返回 → start_thread → exit系统调用
  → 内核清理 → 清零 tid → futex唤醒 → 父线程继续
```

## pthread_detach 的实现

```c
int __pthread_detach(pthread_t th)
{
    struct pthread *pd = (struct pthread *) th;

    // 验证线程描述符
    if (INVALID_NOT_TERMINATED_TD_P(pd))
        return ESRCH;

    // CAS 设置 joinid（标记为 detached）
    if (atomic_compare_and_exchange_bool_acq(&pd->joinid, pd, NULL)) {
        if (IS_DETACHED(pd))
            return EINVAL;  // 已经是 detached
        // 有线程正在 join，标准未定义此行为
    } else {
        // 检查线程是否已终止
        if ((pd->cancelhandling & EXITING_BITMASK) != 0)
            __nptl_free_tcb(pd);  // 立即释放资源
    }

    return 0;
}
```

### detached 线程的退出

在 `start_thread` 的末尾：

```c
if (IS_DETACHED(pd))
    __nptl_free_tcb(pd);  // 自动释放 TCB
else
    // 保留 TCB，等待 pthread_join
```

## 关键设计总结

| 机制 | 实现方式 | 作用 |
|------|---------|------|
| 线程创建 | `clone3` 系统调用 | 创建共享资源的轻量级执行单元 |
| 线程同步 | futex（快速用户态互斥） | 用户态快速路径 + 内核态慢速路径 |
| 线程结束通知 | `CLONE_CHILD_CLEARTID` | 内核自动清零 tid，唤醒 join 线程 |
| 资源回收 | detached 自动释放 / join 手动释放 | 防止内存泄漏 |
| 取消机制 | 异步/延迟取消 + 取消点 | 安全地终止线程 |
