# 底层解析

## phread_create

从用户态线程创建入手，看看都发生了什么

1、初始化和准备工作

-   检查 `__libc_single_threaded` 标志，执行延迟初始化，设置多线程标志 `multiple_threads`（在系统调用信息部分）
-   获取线程属性 `pthread_attr`，包括栈的大小、保护区大小、调度参数等，并检查是否需要使用默认的还是用户提供的参数

2、分配线程控制块（TCB）

-   分配 `pthread` 结构体，为新线程初始化 TCB。此时设置一些基础属性，如线程函数 `start_routine` 和函数参数 `arg`
-   初始化 `stackblock` 和 `stackblock_size` 成员，设置栈的起始地址和大小
-   为线程分配栈空间，处理 `stackblock`、`stackblock_size` 和 `guardsize`

3、设置线程状态与标志

-   根据传入的线程属性，设置 `flags`，初始化 `cancelhandling`、`exiting`、`stopped_start` 等状态标志（线程状态与标志）
-   如果线程被标记为 C11 线程（`c11` 标志），则执行相应的初始化

4、配置调度信息

-   复制父线程的调度策略 `schedpolicy` 和调度参数 `schedparam`
-   如果线程属性要求使用特定的调度参数或策略，则更新 `schedpolicy` 和 `schedparam`，并设置相应的 `flags`
-   配置 `result` 用于存储线程函数的返回值

5、信号屏蔽设置

-   设置 `sigmask`，屏蔽所有信号，防止新线程在启动时受到干扰（信号处理部分）

6、TCB 特殊设置

-   设置栈保护的相关信息，如 `cleanup_jmp_buf`、异常处理 `exc`（异常处理与栈展开部分）
-   配置 TLS 信息，包括 `specific_1stblock` 和 `specific`（线程局部存储部分）

7、线程同步与锁的设置

-   初始化锁 `lock` 和 `setxid_futex`，用于线程间同步（线程同步与锁部分）
-   如果线程是robust互斥锁持有者，配置 `robust_head` 和 `robust_prev`（互斥锁与条件变量部分）

8、**创建线程**

-   调用 `create_thread`，启动新线程
-   如果线程创建失败，释放分配的资源

9、恢复父线程的状态

-   恢复父线程的信号掩码 `sigmask`，确保父线程的信号设置不受影响

总的来说，在create_thread之前，把线程的用户栈、调度信息、锁信息、线程函数信息都搜集存储了，之后进入create_thread部分

## create_thread

### kernel_clone

-   首先，父线程会获得子线程对应的锁，这样是为了保证，即便内核部分kernel_clone之后，子线程被立即调度了，也会因为无法得到锁而被挂起，通过这样来实现对新线程启动的控制
-   之后构建clone_args进行系统调用，调用clone，到了内核中就是kernel_clone

```c
{
    struct kernel_clone_args args = {
        .flags      = (lower_32_bits(clone_flags) & ~CSIGNAL),
        .pidfd      = parent_tidptr,
        .child_tid  = child_tidptr,
        .parent_tid = parent_tidptr,
        .exit_signal    = (lower_32_bits(clone_flags) & CSIGNAL),
        .stack      = newsp,
        .tls        = tls,
    };

    return kernel_clone(&args);
}
```

-   对比进程的kernel_clone，线程这边就有很多区别
    -   对于 copy_files，原来是调用 dup_fd 复制一个 files_struct 的，现在因为 CLONE_FILES 标识位变成将原来的 files_struct 引用计数加一
    -   对于 copy_fs，原来是调用 copy_fs_struct 复制一个 fs_struct，现在因为 CLONE_FS 标识位变成将原来的 fs_struct 的用户数加一
    -   对于 copy_sighand，原来是创建一个新的 sighand_struct，现在因为 CLONE_SIGHAND 标识位变成将原来的 sighand_struct 引用计数加一
    -   对于 copy_signal，原来是创建一个新的 signal_struct，现在因为 CLONE_THREAD 直接返回了
    -   对于 copy_mm，原来是调用 dup_mm 复制一个 mm_struct，现在因为 CLONE_VM 标识位而直接指向了原来的 mm_struct
-   对于id部分，如果是新的进程，tgid就是pid，而新加入的线程，tgid就是进程pid
-   对于real_parent和parent_exec_id
    -   相当于新创建的task，和创建它的task共享一个父task
    -   同时，新task的 parent_exec_id 与当前task的 parent_exec_id 相同
    -   对于线程这边也好理解，进程下所有的线程的父task都是初始的这个进程的task

### __clone3

对于上面部分，实际上是这一条代码进行的系统调用

```c
int ret = __clone_internal (&args, &start_thread, pd);
```

而对于这个_clone_internal，实际是封装的是clone3，而clone3具体的部分如下

```c
ENTRY (__clone3)
    /* Sanity check arguments.  */
    movl    $-EINVAL, %eax
    test    %RDI_LP, %RDI_LP    /* No NULL cl_args pointer.  */
    jz  SYSCALL_ERROR_LABEL
    test    %RDX_LP, %RDX_LP    /* No NULL function pointer.  */
    jz  SYSCALL_ERROR_LABEL
    /* Save the cl_args pointer in R8 which is preserved by the
       syscall.  */
    mov %RCX_LP, %R8_LP
    /* Do the system call.  */
    movl    $SYS_ify(clone3), %eax
    /* End FDE now, because in the child the unwind info will be
       wrong.  */
    cfi_endproc
    syscall
    test    %RAX_LP, %RAX_LP
    jl  SYSCALL_ERROR_LABEL
    jz  L(thread_start)
    ret
```

可以看到，调用了kernel_clone返回之后，先判断是否成功创建，之后根据返回只，如果为0，即在子task，才会进一步进行thread_start，真正执行线程内部的函数，对于父task就直接ret回调用者了

```c
L(thread_start):
    cfi_startproc
    /* Clearing frame pointer is insufficient, use CFI.  */
    cfi_undefined (rip)
    /* Clear the frame pointer.  The ABI suggests this be done, to mark
       the outermost frame obviously.  */
    xorl    %ebp, %ebp
    /* Set up arguments for the function call.  */
    mov %R8_LP, %RDI_LP /* Argument.  */
    call    *%rdx       /* Call function.  */
    /* Call exit with return value from function call. */
    movq    %rax, %rdi
    movl    $SYS_ify(exit), %eax
    syscall
    cfi_endproc
    cfi_startproc
```

线程函数返回值存储在 %rax 中，将它作为参数传递给 exit 系统调用，以便在子进程中退出，通过 syscall 指令执行 exit 系统调用，退出线程。

仔细看int ret = __clone_internal (&args, &start_thread, pd) 这里会发现，这个start_thread并不是线程的函数，线程中的函数存储在start_routine中，而这个start_thread其实是另外一个函数

### 父线程和子线程的执行路线

在进一步讲子线程中的start_thread之前，可以先整体的梳理一下父子线程的执行脉络

1.  首先就只有父线程，调用pthread_create时候，对应内核就是pthread_create_2_1函数，首先就是像上面总结过的，准备好新线程的用户栈资源、调度信息、锁信息、线程函数信息都准备好，之后create_thread，之后进入clone3的部分
2.  clone3之中**调用kernel_clone，根据信息和标志位真正的创建子task，同时放入队列，就可以被调度运行了**
3.  在clone3中，根据返回值的不同，**子线程会进一步进入start_thread**，而**父线程会ret回create_thread**，父子线程在这里分道扬镳，这里父线程根据返回值，来判断是否成功创建子线程，之后进行一些后续处理同时返回__pthread_create_2_1

值得注意的是在上面这些操作中，关于锁的一些处理，在create_thread中有这样的代码

```c
pd->stopped_start = *stopped_start;
if (__glibc_unlikely (*stopped_start))
    lll_lock (pd->lock, LLL_PRIVATE);
```

这个stopped_start是在pthread_create_2_1中设置，如果当前模式是要求调试功能的话，会将它设置为true，利用它实现子线程在父线程完成必要的设置之前不会继续执行，父线程在pthread_create_2_1的最后会解锁，确保了线程的一个有序运行

现在重新回到start_thread的分析，而子start_thread的第一步就是观察stopped_start位，如果设置了，就通过获得锁的方式将子线程挂起等待，获得到锁（即父线程结束）之后就立即解锁，相当于锁这里就仅仅是个同步父子线程的作用

对于start_thread之后的操作，可以看到子线程的一整个生命周期

1、资源管理和初始化

-   设置本地变量和初始化环境：**resp = &pd->res 设置解析器状态，**ctype_init() 初始化 C 语言相关的数据结构，设置堆栈名称 (name_stack_maps) 等。这些操作确保新线程有一个干净的执行环境
-   TLS (线程局部存储) 注册：如果需要，子线程会在内核中注册 TLS 数据区（rseq 区域），这为线程提供了一种存储私有数据的方法，避免全局变量带来的竞争问题

2、线程执行

-   设置线程取消点：使用 setjmp 设置线程的取消点，start_thread 中为异常处理和取消机制做好准备
-   执行用户的线程函数：线程函数 (pd->start_routine) 是子线程的主要工作逻辑，它会被调用，执行用户代码。执行完毕后，返回值会被保存到 pd->result 中

3、资源清理与线程退出

-   线程局部变量的管理：执行完用户代码后，调用 TLS 数据的析构函数，并释放线程局部存储。这些步骤确保在线程退出之前完成所有线程资源的清理
-   锁的解除和资源的释放：子线程退出前，futex 和锁机制会用于同步退出过程，避免资源竞争。对于某些线程资源（如健壮性互斥锁），需要特别处理以确保线程退出时的状态一致
-   如果当前线程是最后一个用户线程，则会调用 exit(0) 终止整个进程

## 其他pthread函数的实现

### pthread_join

```c
___pthread_join (pthread_t threadid, void **thread_return)
```

等待一个threadid的线程结束

pthread_join内部依靠__pthread_clockjoin_ex实现，用于实现线程的同步等待功能。它允许主线程等待指定的目标线程终止，同时还支持根据给定的时间限制进行等待。函数的逻辑涉及到检测线程的状态、等待线程退出，以及释放资源。

```c
if (block)
    {
      /* During the wait we change to asynchronous cancellation.  If we
     are cancelled the thread we are waiting for must be marked as
     un-wait-ed for again.  */
      pthread_cleanup_push (cleanup, &pd->joinid);

      /* We need acquire MO here so that we synchronize with the
         kernel's store to 0 when the clone terminates. (see above)  */
      pid_t tid;
      while ((tid = atomic_load_acquire (&pd->tid)) != 0)
        {
         /* The kernel notifies a process which uses CLONE_CHILD_CLEARTID via
        futex wake-up when the clone terminates.  The memory location
        contains the thread ID while the clone is running and is reset to
        zero by the kernel afterwards.  The kernel up to version 3.16.3
        does not use the private futex operations for futex wake-up when
        the clone terminates.  */
      int ret = __futex_abstimed_wait_cancelable64 (
        (unsigned int *) &pd->tid, tid, clockid, abstime, LLL_SHARED);
      if (ret == ETIMEDOUT || ret == EOVERFLOW)
        {
          result = ret;
          break;
        }
    }

      pthread_cleanup_pop (0);
    }
```

核心功能代码就是这部分，等待线程的tid设置为0，在此之前利用futex机制将主线程挂起，tid 清零是 CLONE_CHILD_CLEARTID 机制的一部分，CLONE_CHILD_CLEARTID 是一种用于线程终止时自动通知机制的系统调用标志，在线程退出时由内核自动清除线程 ID (tid) 并通过 futex 唤醒等待在该地址上的其他线程，在当tid被清零时候，主线程被唤醒，执行最后的清理部分，把TCB的资源彻底清理，同时tid置-1，代表线程彻底终止

### phread_detach

在start_thread中，有这样一段代码

```c
if (IS_DETACHED (pd))
    /* Free the TCB.  */
    __nptl_free_tcb (pd);
```

相当于对于detached的线程，这里就会自动清理资源了，而对于detach代码本身其实非常简单，就是单纯做个标记

```c
int
___pthread_detach (pthread_t th)
{
  struct pthread *pd = (struct pthread *) th;

  /* Make sure the descriptor is valid.  */
  if (INVALID_NOT_TERMINATED_TD_P (pd))
    /* Not a valid thread handle.  */
    return ESRCH;

  int result = 0;

  /* Mark the thread as detached.  */
  if (atomic_compare_and_exchange_bool_acq (&pd->joinid, pd, NULL))
    {
      /* There are two possibilities here.  First, the thread might
     already be detached.  In this case we return EINVAL.
     Otherwise there might already be a waiter.  The standard does
     not mention what happens in this case.  */
      if (IS_DETACHED (pd))
    result = EINVAL;
    }
  else
    /* Check whether the thread terminated meanwhile.  In this case we
       will just free the TCB.  */
    if ((pd->cancelhandling & EXITING_BITMASK) != 0)
      /* Note that the code in __free_tcb makes sure each thread
     control block is freed only once.  */
      __nptl_free_tcb (pd);

  return result;
}
```
