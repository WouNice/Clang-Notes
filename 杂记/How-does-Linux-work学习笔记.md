# 《Linux 是怎么工作的》学习笔记

## 用户模式实现的功能

### 系统调用：用户态→内核态的唯一桥梁

| 概念 | 说明 |
|------|------|
| **用户模式** | 进程正常运行的 CPU 模式，权限受限 |
| **内核模式** | 操作系统内核运行的 CPU 模式，可执行所有指令 |
| **系统调用** | 用户态请求内核服务的唯一手段 |

- CPU 模式切换机制：用户态进程通过**系统调用**触发 `syscall` 指令 → CPU 切换到内核模式 → 执行内核代码 → 返回用户模式
- 系统调用只能通过**汇编指令**发起（如 x86_64 的 `syscall`），glibc 提供的 C 函数只是包装
- 所有 I/O 操作、进程创建、内存分配等必须经系统调用进入内核

### strace 追踪系统调用

```bash
# 追踪程序的所有系统调用
strace ./hello

# 常用选项
strace -o trace.log ./hello    # 输出到文件
strace -T ./hello              # 显示每个系统调用耗时
strace -tt ./hello             # 显示时间戳
```

### sar 采集 CPU 时间分配

```bash
sar -u 1   # 每秒采集一次 CPU 使用率
```

输出字段：`%user`（用户态）、`%system`（内核态）、`%idle`（空闲）

## 进程管理

### fork()：创建子进程

```c
pid_t pid = fork();
// 返回值：0 给子进程，子进程 PID 给父进程，-1 表示失败
```

- fork() 后子进程是父进程的**副本**
- 子进程获得独立的 PID，但代码/数据/堆栈最初与父进程共享物理页面

### execve()：替换进程映像

```c
execve("/bin/ls", argv, envp);
// 成功时不返回（整个进程映像被替换），失败时返回 -1
```

- 替换进程的代码段、数据段、堆栈为新程序
- **PID 不变**——进程还是那个进程，只是内容换了
- 典型模式：`fork()` + `execve()` = 创建新进程运行新程序

### ELF 格式

可执行文件的 ELF 格式包含进程加载所需的辅助信息：

```bash
readelf -h ./hello       # 查看 ELF 头信息（入口点、架构等）
readelf -S ./hello       # 查看节区表（代码段、数据段等）
cat /proc/pid/maps       # 查看进程的虚拟内存映射
```

### 进程终止

| 函数 | 行为 |
|------|------|
| `_exit()` | 直接退出，不刷新 stdio 缓冲区 |
| `exit()` | 刷新 stdio 缓冲区，调用 atexit 注册函数，然后退出 |

### 僵死进程（Zombie）

- 子进程退出后，若父进程未调用 `wait()`，子进程变为**僵死进程**
- 僵死进程已释放几乎所有资源，仅保留 PID 和退出状态
- 父进程调用 `wait()` 后，僵死进程才被完全清除
- 如果父进程先于子进程退出，子进程变为**孤儿进程**，由 init 进程（PID 1）收养

## 进程调度器

### 时间片轮询

- 每个 CPU 核心同一时刻只能运行一个进程
- 调度器通过**时间片**机制让多个进程轮流使用 CPU
- 上下文切换：保存当前进程状态 → 选择下一个进程 → 恢复其状态

```bash
ps -eo pid,stat,comm    # 查看进程状态
```

### 空闲进程

- 当没有可运行进程时，CPU 运行 **idle 进程**（PID 0）
- idle 进程使 CPU 进入省电状态，降低功耗和发热

### 吞吐量 vs 延迟

- **吞吐量**：单位时间内完成的处理量
- **延迟**：从发出请求到获得响应的时间
- 两者此消彼长：时间片越长吞吐越高但延迟越大，反之亦然

### nice 值

- nice 值范围：-20 ~ 19（实际使用 -19 ~ 20）
- **值越低优先级越高**，默认为 0
- 只有 root 可以设置负值（提高优先级）

```bash
nice -n 10 ./command    # 以 nice 值 10 运行（低优先级）
renice -n -5 -p 1234   # 调整运行中进程的优先级
```

### CPU 亲和性

```bash
taskset -c 0 ./command    # 将进程绑定到 CPU 0 运行
```

- 通过 `sched_setaffinity()` 系统调用实现
- 绑定 CPU 可减少缓存失效，但降低调度灵活性

## 内存管理

### 本章核心

虚拟内存是现代 OS 最关键的抽象之一。理解虚拟内存，就理解了进程隔离、内存保护和多任务的基础。

### 虚拟内存解决三大问题

1. **内存碎片化**：通过页表映射，将物理内存碎片整合为虚拟地址空间的连续区域
2. **访问越界**：每个进程独立虚拟地址空间 + 页表项权限控制，进程无法访问其他进程或内核内存
3. **多任务冲突**：各进程独立地址空间，无需关心物理地址布局

### 页表与缺页中断

- 所有内存以**页**（Page）为单位管理，x86_64 页面大小 **4 KB**
- 页表项记录虚拟地址与物理地址的对应关系
- 访问未映射的虚拟地址 → **缺页中断** → 内核分配物理内存或发送 SIGSEGV

### 请求分页（Demand Paging）

- **核心思想**：仅在进程首次访问页面时才分配物理内存
- 三种页面状态：未分配 / 已分配虚拟但无物理页 / 已分配物理页
- `malloc()` 分配的是**虚拟内存**，物理内存推迟到实际访问时通过缺页中断分配

```bash
sar -r 1     # 观察内存使用量
sar -B 1     # 观察缺页中断频率
ps -eo pid,comm,vsz,rss,min_flt,maj_flt   # 进程级虚拟/物理内存统计
```

### 写时复制（COW）

- `fork()` 时**仅复制页表**，父子进程共享物理页面，写入权限失效
- 任一方写入 → 缺页中断 → 复制该页面 → 各自独立
- 优势：fork() 极快；若子进程 fork 后立即 exec，则完全不需要复制物理页面

### Swap（交换）

- 将外部存储器暂代内存：**换出**（物理内存→交换分区）+ **换入**（交换分区→物理内存）
- ⚠️ 外部存储器比内存慢数个数量级，**系统抖动**（频繁换入换出）可致系统近乎瘫痪
- `sar -W` 监控换入换出频率，`sar -S` 监控交换分区使用趋势
- **硬性页缺失**（需访问外部存储器）vs **软性页缺失**（不需访问外部存储器）

### OOM Killer

- 物理内存耗尽 → OOM Killer 强制终止进程释放内存
- **不可预测**哪个进程被杀——生产环境必须避免
- `vm.panic_on_oom = 1`：OOM 时宕机（某些生产环境偏好确定性宕机）

### 多级页表

- 单层页表在 x86_64 上需要 256 GB → 不可行
- x86_64 采用 **4 级页表**，仅对已使用的虚拟地址范围创建页表项
- `sar -r ALL` 中 `kbpgtbl` 字段显示页表占用的物理内存量

### 标准大页与透明大页

| 特性 | 标准大页 | 透明大页 |
|------|----------|----------|
| 大小 | 2 MB（x86_64） | 自动合并连续 4KB 页面 |
| 用法 | `mmap(MAP_HUGETLB)` 或程序配置 | 内核自动管理 |
| 优点 | 减少页表项，加速 fork() | 零配置 |
| 缺点 | 需手动配置 | 合并/拆分时可能引起局部性能下降 |

```bash
cat /sys/kernel/mm/transparent_hugepage/enabled   # 查看透明大页状态
echo never > /sys/kernel/mm/transparent_hugepage/enabled  # 禁用
```

### 文件映射（mmap）

- 将文件内容映射到虚拟地址空间，按访问内存的方式访问文件
- 比传统 `read()/write()` 更高效，减少一次内核↔用户空间的数据拷贝
- 写入映射区域 → 内核在适当时机写回文件

## 存储层次

### 存储层次结构

```
CPU 寄存器 → L1 缓存 → L2 缓存 → L3 缓存 → 内存 → 外部存储器
  最快/最小                                    最慢/最大
```

- 层间数据以**缓存行**为单位传输（x86_64 为 **64 字节**）

### 局部性原理

| 类型 | 说明 | 示例 |
|------|------|------|
| 时间局部性 | 刚被访问的数据很快会被再次访问 | 循环变量 |
| 空间局部性 | 被访问数据附近的数据很快也会被访问 | 顺序遍历数组 |

- 缓存之所以有效，正是利用了局部性原理

### TLB（Translation Lookaside Buffer）

- 页表的**缓存**，加速虚拟地址→物理地址的转换
- TLB 未命中 → 需要遍历多级页表 → 性能损失

### 页面缓存（Page Cache）

- 内核将读取过的文件内容缓存在内存中
- **读加速**：命中页面缓存时，读取速度约为直接读磁盘的 **~20 倍**
- **写策略**：先写入页面缓存（标记为**脏页**），稍后异步写回磁盘（write-back）

### 脏页回写参数

| 参数 | 路径 | 说明 |
|------|------|------|
| `dirty_writeback_centisecs` | `/proc/sys/vm/` | 脏页回写线程唤醒间隔（百分之一秒） |
| `dirty_background_ratio` | `/proc/sys/vm/` | 脏页占比达此值开始异步回写 |
| `dirty_ratio` | `/proc/sys/vm/` | 脏页占比达此值同步回写（阻塞写入进程） |

```bash
echo 3 > /proc/sys/vm/drop_caches   # 手动清理页面缓存（需 root）
```

### 超线程（Hyper-Threading）

- 一个物理核心模拟为**两个逻辑 CPU**
- **理想提升 20~30%**，绝非 2 倍
- 对 I/O 等待型任务效果较好，对 CPU 密集型任务效果有限

## 第 6 章 文件系统

### VFS（Virtual File System）

- Linux 通过 VFS 为所有文件系统提供统一接口
- 用户程序无需关心底层是 ext4、XFS、Btrfs 还是网络文件系统

### 数据 vs 元数据

| 类型 | 说明 | 示例 |
|------|------|------|
| 数据 | 文件的实际内容 | 文本、图片、视频 |
| 元数据 | 关于数据的数据 | 文件大小、权限、时间戳、属主 |

### 一致性保护

| 方法 | 文件系统 | 原理 |
|------|----------|------|
| 日志（Journal） | ext4, XFS | 先将元数据变更写入日志，再写入实际位置 |
| 写时复制（CoW） | Btrfs | 修改时写入新位置，原子切换指针 |

- ext4 日志模式：`data=ordered`（默认）、`data=journal`（最安全最慢）、`data=writeback`（最快，崩溃后可能数据不一致）

### 设备文件

| 类型 | 特征 | 示例 |
|------|------|------|
| 字符设备 | 按字符流访问 | `/dev/null`、`/dev/tty` |
| 块设备 | 按块随机访问 | `/dev/sda`、`/dev/nvme0n1` |

### 特殊文件系统

| 文件系统 | 挂载点 | 特点 |
|----------|--------|------|
| tmpfs | `/dev/shm`、`/tmp` | 内存文件系统，断电消失 |
| procfs | `/proc` | 进程和内核信息 |
| sysfs | `/sys` | 硬件和驱动信息 |
| cgroupfs | `/sys/fs/cgroup` | 控制组（资源限制） |
| NFS | 远程挂载 | Linux/Unix 间共享 |
| CIFS/SMB | 远程挂载 | 与 Windows 共享 |

### Btrfs 特色功能

| 功能 | 说明 |
|------|------|
| 多设备存储池 | 多块磁盘组合为一个存储池 |
| 快照 | 瞬间创建文件系统的只读/可写快照 |
| RAID | 内置 RAID 0/1/5/6/10 |
| 校验和 | 数据和元数据均有校验和，检测静默数据损坏 |
| 子卷 | 类似独立分区，可独立挂载 |

## 外部存储器

### HDD vs SSD

| 特性 | HDD | SSD |
|------|-----|-----|
| 原理 | 磁盘旋转 + 磁头移动 | 闪存芯片，无机械部件 |
| 延迟 | 寻道 + 旋转延迟（ms 级） | 无机械延迟（μs 级） |
| 随机访问 | 极慢 | 快 |
| 磨损 | 无 | 闪存有写入寿命 |

### 顺序访问远优于随机访问

- 对 HDD 尤为显著（消除寻道/旋转延迟）
- 即使 SSD，顺序访问吞吐量也远大于随机访问
- 大 I/O 请求量可提升吞吐量至设备上限

### 通用块层与 I/O 调度器

```
用户进程 → 系统调用 → VFS → 通用块层 → 设备驱动 → 硬件
                              ↑
                        I/O 调度器（合并 + 排序 + 预读）
```

| I/O 调度器功能 | 说明 |
|---------------|------|
| 合并 | 将相邻 I/O 请求合并为一个 |
| 排序 | 按起始扇区排序，减少寻道（HDD） |
| 预读 | 预测并提前读取后续数据 |

- HDD：I/O 调度器效果显著（减少寻道时间）
- SSD：大请求量时排序开销 > 收益，建议使用 `none`（noop）调度器

### O_DIRECT（直接 I/O）

- 绕过页面缓存，直接在用户缓冲区和设备间传输
- 适用于数据库等自行管理缓存的程序
- 要求用户缓冲区 4KB 对齐

### I/O 性能观测

```bash
iostat -x 1    # 每秒查看设备 I/O 统计
```

关键字段：`%util`（设备利用率）、`await`（平均 I/O 等待时间）

### I/O 优化原则

1. **数据存放在连续区域** → 减少寻道
2. **合并连续请求** → 减少请求次数
3. **顺序访问大数据量** → 最大化吞吐量
4. SSD 使用 `none` 调度器
5. 自管理缓存的程序考虑 `O_DIRECT`
